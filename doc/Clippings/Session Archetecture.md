### SegForge Session Architecture: Linking Sessions, Images, Segments, and Prompts

Within SegForge, a **Session** serves as the primary container for a multi-image segmentation workflow. Because a single user session spans multiple source images, produces numerous discrete segments (including sub-image crops), and generates corresponding prompt data, maintaining a rigorous structural relationship between these elements is critical for traceability, auditing, and iterative refinement.

### 1\. Hierarchical Data Entities

The session ecosystem organizes data across four core layers:

- **Session:** The top-level workspace container representing an independent working state. It tracks metadata, configuration profiles, and a collection of processed assets.
- **Image:** The individual source media imported into the session. A session contains an ordered collection of images (e.g., video frames, batch uploads, or multi-page documents).
- **Segment / Sub-Image:** The discrete outputs generated by the segmentation process. A single image can yield any number of variable segments. These include both vector/raster boundary masks and physical sub-images (cropped regions of interest extracted from the original art).
- **Prompt:** The contextual instructions, text tokens, or spatial conditioning parameters (e.g., bounding boxes, point coordinates, or descriptive text) that drive the segmentation model.

### 2\. Multi-Level Relational Linking

To ensure prompts remain meaningfully bound to their downstream targets across the session lifecycle, SegForge enforces a multi-directional linkage pattern:

$$
Session⟶Image(1:N)⟶Segment(1:M)⟷Prompt(N:M)
$$

- **Image-to-Segment Mapping:** Every segment is explicitly tied back to its parent source image via an image identifier. If a segment is a sub-image crop, its pixel coordinates are mapped relative to the root image grid.
- **Prompt-to-Image Linkage:** Prompts can be scoped at the global image level (e.g., a universal text prompt applied to an entire video frame or photograph to guide initial object discovery).
- **Prompt-to-Segment Linkage:** Prompts can also be scoped locally to specific segments or sub-images (e.g., iterative refinement prompts, exclusion tags, or specific visual descriptions tied to an isolated cutout).
- **Many-to-Many Traceability:** Because a single prompt can inspire multiple segments (e.g., finding all instances of an object class across an image), and a single segment can be the result of a composite prompt chain (initial grounding prompt followed by refinement prompts), the architecture preserves the associative mapping to audit how any given sub-image was derived.

### 3\. Persistence and State Management

When a user executes a **save**, **resume**, or **delete** action on a session:

- **Serialization:** All relational links between sessions, images, extracted sub-image byte arrays, and linked prompt metadata are packed into a unified storage snapshot.
- **Resumability:** Restoring a session instantly reconstructs the node graph and associative array structures, allowing the user to pick up complex multi-image segmentation pipelines exactly where they left off without losing the contextual lineage between prompts and visual sub-assets.
